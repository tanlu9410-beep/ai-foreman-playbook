# 派单（dispatch）

工单合同、按活选工人、常驻队列与认领。总览见 [`overview.md`](overview.md)；票板见 [`ticket.md`](ticket.md)；隔离与合入见 [`worktree.md`](worktree.md) / [`land.md`](land.md)。给搭体系的 AI：字段名、拒单原因、认领事务形状都可以原样做成闸。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。路由与认领主体 **Does**。`hard_readonly` 路由跳过、过期收口扫、缺完成条件硬拒：**Recommended / not implemented**。写单缺窄 `allowed_paths` 应拒：**In progress**（作者系统正在改）。施工单终态：`completed` | `failed` | `expired` | `blocked` | `cancelled` | `late_rejected`。

## 解决什么问题

「谁来做」如果靠工头临场猜，会把付费活派给已暂停的池、把写单派给只读席、或在工头这一拍里同步等工人跑完——窗一睡，单就丢。缺票号、没范围、口头「做完了」的施工单也无法验收。

派单要把一次可验收的执行写成合同，按任务类型选池，入队后由常驻进程认领。拒绝必须带原因，不进队列。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 贵池要花钱时点头；重启类工单给当面授权原话 | 选模型、记 git 范围、盯队列 |
| 工头 AI | 写合同：票号、目标、完成条件、`task_kind`、`allowed_paths`、模式、验证方式；读结果验收 | 在同一拍里把活做完；关掉复核；用口头「done」关票 |
| 工人 AI | 只在合同范围内施工 | 自选产品目标；整仓提交 |
| 机器 | 校验合同、按总表路由、入队、同事务认领、看护、过期/续跑、拒单写原因 | 产品判断；把额度未知当成「有空位」 |

## 最小版怎么做

1. **一张路由总表**（JSON）：`version`（正整数，每次改都加一）、`pools[]`、`task_kinds`（任务类型 → 有序 pool id，即后备顺序）。加载时整表 schema 校验；通过则刷新 last-good；坏表回退 last-good 并警告；两份都不可用则拒绝依赖总表的派单。最小示例见 [`FOR-AI.md`](../../FOR-AI.md) §5。
2. **池字段（含义）**：`id`、`backend`、`model`、`source_class`、`billing`、`quota_windows`、`needs_owner_ok`（人必须授权花费）、`hard_readonly`（不该接写单；路由层按它跳过写单是 **Recommended / not implemented**，写边界目前靠 `mode` 和合入门）、`memory_weight`、`expires_at`（日期或 null）、`status`（`active` / `paused` / `banned`）、`reason`（status 非 active 时必填）。可选 `paused_until`（到点自动恢复）、以及「零保留到期」类只挡私密任务类型的截止字段。
3. **施工合同**：票号必填；目标必填；完成条件；`allowed_paths`（仓相对路径）；`mode`（`read_only` / `edit_no_commit` / `verify`）；报告路径。写单缺窄范围 **应拒单**（**In progress**）。空清单不得当成「不改文件」。
4. **创建只入队**（`queued`）。常驻认领者在**同一写事务**里：数正在跑的、查路径锁/容量，再 `queued → running`。看护进程把认领者拉活。认领了但没拉起进程的退回队列；已经拉起、进程没了 → `failed`。
5. **拒单写原因**，不进队列。沉默是 bug。

额度未知或过期快照：既不当「已满」，也不当「有额度去抢」。

## 我们现在的版本（2026-09）

模型名、池 id、权重随表换；换表只改 JSON，不要把名字写进闸门代码。下面不抄私有池名。

### 工单合同

- **Does。票号必填。** 非法或缺失直接拒；测试模式才可省略。
- **Does。目标必填。** 空 goal 拒。
- **Recommended。** 完成条件缺省用占位语句，不把「有票」当成合同完整。可改成硬拒。
- **`allowed_paths`。In progress：** 写单缺窄范围应拒。作者系统目前仍把空 / `.` / `/` 当成整仓并警告、不拒。路径必须是仓相对路径。
- **Does。路径锁。** 认领时，非只读且路径重叠的写单不能同时跑；`.` 与任何路径重叠。`task_kind=restart` 不占锁。
- **Does。模式。** 只允许 `read_only` / `edit_no_commit` / `verify`。
- **Does。报告路径。** 可选；必须落在约定的文档目录，非法硬拒。只读/核对单可在创建后自动指定。
- **Does。复核不能关。** `review_required=false` 拒。
- **Does。重启形工单要人的当面原话**（字段 `owner_ok`）。`task_kind=restart` 或目标/条件里像在下重启令，缺原话就拒。
- **Does。非工头席只能派只读。**
- **Does。提交/报告条款自动追加。** 工单正文提到 commit/提交，末尾追加死清单提交方式。死清单定义：清单 ⊆ `allowed_paths`，否则拒。见 [`commit.md`](commit.md)。

### 按活选工人

- **Does。总表加载。** 校验、刷 last-good、坏表回退；两份都坏则该单拒绝。
- **Does。省略 backend 必须写 `task_kind`。** 按 `task_kinds[kind]` 顺序试池，第一个过全部规则的赢。选不出则拒，并把每个池的 skip 原因带回。
- **Does。跳过。** 暂停/封禁（`paused_until` 已过的 paused 算 active）、过期、私密类型不合格、后端不可用、额度耗尽或新鲜窗口接近上限、`needs_owner_ok` 但没有授权、贵模型没写 `reason`、隔离写单但该后端引擎未开、提交类活派到写不了 `.git` 的沙箱后端。额度快照不新鲜不当成已满。
- **Does。贵模型要写理由。** 总表里标了「需要理由」的档，无 `reason` 则跳过或拒。
- **Does。质量分工（表顺序，不是另一套代码）。** 抄写走便宜/免费池，不进施工旗舰、也不占最低档施工后备。验收首选与施工首选错开供应商。提交 / 重启 / 运维不进写不了 `.git` 的沙箱后端。换模型只改表。
- **Does。显式 backend 且该后端所有池仍暂停 → 拒，** 让工头改走 `task_kind` 自动路由。
- **Recommended / not implemented。`hard_readonly`。** 字段写在表里，路由**尚未**按它跳过写单。写边界靠 `mode` 白名单和合入门。建议路由层对写单跳过 `hard_readonly=true` 的池。
- **Does。并行上限。** 按后端配置同时跑的个数；最后一个候选即使已达上限也收下，避免全跳空。

### 常驻队列与认领

- **Does。创建落 `queued`。** 工头不等工人跑完。
- **Does。认领者分后端。** 各后端有自己的认领循环；容量计数和 `queued → running` 在同一写事务。容量若在开事务之前数，会超卖。
- **Does。看护。** 发现认领者心跳不在就拉起；积压告警。宿主启动时挂上认领循环。
- **Does。自愈。** 认领后从未出现工作目录 → 退回 `queued`；已拉起但进程死 → `failed`，不重跑以免双开。
- **Does，会再花钱。超时自动续跑。** 工人因轮数用尽或墙钟超时停在半成品：系统**另开一张**续做单（同一后端/范围/票），再计一次费。续做自己再耗尽则告警让工头拆单，不第三次自动开。对人说清楚会再花钱。
- **Does（适配器）。** 工人撞上自己的时限，适配器把 running 标 `expired`。create 用预算分钟算 ttl。
- **Recommended / not implemented。过期收口。** 另有一次扫 queued/running 的收口。常驻循环调用它——作者系统 2026-09 生产路径未见，不要写成已上的硬闸。
- **Does。重启进行中暂停新认领。** 认领前查闸。闸读失败时这条暂停会 fail-open，以免永久卡死队列，**不告警**。见 [`restart.md`](restart.md)。
- **Does。终态是终态。** `blocked` 不能回到 `running`（同一 task id）。

### 拒单写原因（不进队列）

| 原因 | 说明 |
|---|---|
| 无票 / 票号非法 | 硬拒 |
| 无 goal | 硬拒 |
| `review_required=false` | 硬拒 |
| 重启形无 `owner_ok` | 硬拒 |
| 贵模型无 `reason` | 跳过或拒 |
| 总表不可用且本单依赖它 | 硬拒 |
| `task_kind` 选不出池（带 skipped 列表） | 硬拒 |
| 隔离单目标路径主树已脏 | 硬拒 |
| 非工头席写单 | 硬拒 |
| 另一工头席已占同一票 | 硬拒；并发空隙见下 |
| 光杆测试命令（同句没有测试路径） | 硬拒 |
| 沙箱后端写单点名 shell 脚本 / 要求 `git commit` | 硬拒 |
| 省略 backend 且无 task_kind | 硬拒 |
| 写单缺窄 `allowed_paths` | **应拒（In progress）**；目前警告整仓 |

整仓范围、大单拆单：作者系统目前警告，不拒。

## 必须由代码强制的规矩

1. 无票号的施工单拒绝。
2. `review_required=false` 拒绝。
3. 重启形工单无 owner 授权原话拒绝。
4. 写单未写窄 `allowed_paths`：**应拒**（**In progress**）。空清单不得当成「不改文件」。路径仓相对。
5. 容量检查与 `queued → running` 必须在同一写事务。
6. 重启进行中暂停新认领。
7. 终态不可逆；`blocked` 同一 task id 不得回到 `running`。
8. 拒单必须带原因。

不要把 `hard_readonly` 路由跳过、过期收口扫、握手无死清单、缺完成条件写成当前硬闸——那些是 **Recommended** 或 **not implemented**。

## 空隙（如实）

- **并发占票。** 互斥是创建时扫描「另一席是否已持有」。两席同一瞬间创建，可能都过扫描。不是跨席一把排他锁。
- **起跑前崩溃。** 认领了但从未出现工作目录 → 退回 `queued`（**Does**）。空隙在「这行看起来能放下」到写下 `running` 之间。
- **fail-open 不告警。** 过期收口未挂上常驻循环时，queued 可能一直挂着；重启闸读失败时认领不停。没有告警页给人。
- **自动续跑再花钱。** 见上。

## 常见坑与我们怎么补的

1. **工头同步等工人。** 窗超时或休眠，单卡在半空。补：create 只入队；常驻认领；看护拉活。
2. **只认领队列头。** 头一张整仓写单挡住后面的只读单。补：有界扫描，认领**第一张能放下**的，每拍仍最多一张。
3. **额度快照当真理。** 过期的高占用被当成已满，或未知被当成有空位。补：不新鲜的窗口不跳过；未知不抢先。
4. **抄写/验收和施工抢同一家模型。** 贵、且验收会护短。补：总表按 `task_kind` 分池；验收与施工首选错开供应商。换模型只改表。
