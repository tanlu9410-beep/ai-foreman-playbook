# 文档怎么保鲜

进度和规矩若只活在聊天里，下一窗会把过期句子当真。本页管「哪种文件写哪类事实、谁来改、改完怎么不腐烂」。票板本身见 [`ticket.md`](ticket.md)；开窗怎么把这些文件交到下一窗见 [`handoff.md`](handoff.md)。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。本页主体 **Does**。「一种文件一件事」靠纪律，是 **Recommended**。

## 解决什么问题

没有分工时，同一件事实会写进三份文件，三份还会互相打架。常驻说明变成杂物抽屉：情境补丁、一次性教训、已经作废的路径全堆在每拍都要读的前缀里。删掉一行却不记去处，老毛病回来时没人知道该不该加回去。关了票地图还写着旧部件。收工时「我记得写了」——其实没写。

## 交给谁

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| **人** | 要不要改常驻说明（那会让下一窗冷启动）；优先级 | 自己维护地图和进度页 |
| **工头 AI** | 写系统地图、进度页、当前主线、手册现行节；关票时回答地图哪一行变了；收工记账 | 把情境补丁塞进每拍都读的说明 |
| **工人 AI** | 只改工单死清单上的路径（报告、方案、被点名的文档） | 改票板状态；改常驻说明；关票 |
| **机器** | 终态病历、收工三问、主线指纹闸、文档工具的路径白名单 | 判断「这句教训该不该变代码」 |

## 最小版怎么做

### 每种文档只管一件事

| 文件 | 只回答 | 不放 |
|---|---|---|
| **系统地图** | 现在有什么（部件、活 / 停 / 半成品） | 正在做哪张票 |
| **进度页** | 现在做到哪（按时间追加的工程快照） | 服务端口清单 |
| **当前主线** | 这一窗的活（要什么 / 做到哪 / 下一步 / 卡在谁） | 历史、参数、长教训 |
| **手册** | 仅供参考的现行教训（怎么派、怎么重启、踩过的坑的现行值） | 已作废的办法；每拍身份 |
| **票板** | 待办与状态 | 系统结构 |
| **改动台账** | 从常驻说明里挪走的每一行：原文、去处、理由 | 新功能设计 |

读完进度页应能答：在做什么、走到哪、下一步、卡在谁。不写参数。

地图状态词建议固定：活 / 停 / 半成品 / 未确认。未核过的标未确认，不编。

### 教训放哪

顺序是硬的：

1. **能变成代码闸的，变成代码。** 拒单、写后自检、自动记账。
2. **不能闸的，放在出事地点的弹窗**（工具返回、合入失败原因、钩子）。情境发生时才出现。
3. **最后才进手册。** 手册是现行值索引，不是第三份真源。

同一条教训写进手册两次，就是该变成代码却没变。第三句提醒是失败。

### 常驻说明

每拍都进模型前缀的文件，只放每轮都用得上的东西：身份、分工、人闸、提交禁令。情境补丁、某张票的修法、一次性措辞，不要进前缀。

删一行必须在改动台账留去处：旧原文、搬到哪、为什么。拿不准就留。老毛病回来，先查台账再决定换不换回去。不硬删。

台账一行的最小形状（只抽象格式，不要抄私人原话）：

```text
| # | 旧原文 | 去处 | 理由 |
| 1 | （被挪走的那一句） | 新位置或「改写成规则」 | 为什么不再放常驻说明 |
```

### 关票同步地图 · 收工记账

关票时必须回答：本次让进度页 / 系统地图哪一行变了？没变写 `no change`。结构、路径、身份、状态机变了，工头在关票前改对应地图行。普通局部 bug 不必为写文档而写文档。

收工时当场说清：结论写进了地图 / 进度 / 手册 / 票板的哪一句；没写就写上。不要等下一窗。

### 谁来改哪份

| 文件 | 谁写 | 工人怎么碰 |
|---|---|---|
| 系统地图、进度页 | 工头在关票或收工时改 | 默认不改；除非死清单点名某一节 |
| 当前主线 | 工头整张替换；写的时候带上进度页指纹 | 不改 |
| 手册现行节 | 工头改「现在是什么」；历史教训留在手册归档 | 不改常驻说明 |
| 票板 | 工头用票板工具；工人不关票 | 至多追加进展，见 [`ticket.md`](ticket.md) |
| 改动台账 | 工头在挪常驻说明的同一批写入 | 按死清单追加一行，不删旧行 |
| 病历 | 机器在施工单终态自动追加 | 不手改 |
| 方案 / 报告 | 工头开写；工人按死清单追加 | 只动清单路径 |

## 我们现在的版本（2026-09）

下列只抽象职责和格式，不抄源系统正文或私有路径。

- **Does。地图 = 现在有什么。** 一部件表 + 状态词（活 / 停 / 半成品 / 未确认）；数字行会过时，结构路径以地图 + 代码为准。
- **Does。进度页 = 现在做到哪。** 按收工时刻追加一节；读完应能答在做什么、走到哪、下一步、卡在谁；不写参数。
- **Does。当前主线 = 这一窗的活。** 短页，含「怎么算做完」；末行指纹与进度页哈希握手。闸的口径见 [`handoff.md`](handoff.md)：每窗至少拦一次，同窗第二次 fail-open。
- **Does。手册 = 现行教训索引。** 只放「现在是什么」；与长手册冲突以本页为准；改事实必须同批改本页。情境修补放在出事地点，不要塞进每拍身份文件。
- **Does。票板 = 待办与状态。** 见 [`ticket.md`](ticket.md)。普通写文档工具把票板路径列入黑名单，禁止旁路。
- **Recommended。改动台账。** 源系统一次常驻说明搬家用表记录「旧原文 / 去处 / 理由」，规矩是不硬删只挪、拿不准默认留。没有自动扫描。
- **Does。关票要地图说明。** 关票必填 `map_change`。两个真源分开——票板是工作状态，地图目录是系统事实；改变结构则关票前同步地图。
- **Does。收工记账。** 收工触发词附三问；第二拍催未完项。
- **Does。工人按死清单。** 合入只接受清单路径（清单 ⊆ `allowed_paths`，否则拒）；工头用文档工具写方案和本席主线页，不能用它改票板。
- **Does。机器自动记账。** 病历见 [`ticket.md`](ticket.md)。写失败 fail-open，**不告警**。

## 必须由代码强制的规矩

1. 关票必须带 `map_change` 字段（或字面 `no change`）。缺则拒绝。
2. 工头派单时主线指纹与进度页不一致 → 拒绝（每窗至少一次；详见 [`handoff.md`](handoff.md)）。
3. 票板不得经普通写文档工具改写。
4. 工人合入不得带清单外文件。
5. 施工单终态自动写病历。

**Recommended（现在不是硬闸）：** 「一种文件一件事」靠工头纪律。`map_change` 不核对文件是否真改。教训写两次必须变代码——这是元规则（[`FOR-AI.md`](../../FOR-AI.md) §4），不是编译器。常驻说明的删行台账也还没有自动扫描。

## 常见坑与我们怎么补的

1. **同一教训在手册里写第三遍。** 前缀和手册越来越长，闸却还没有。元规则：写两次就变成拒单或自检。
2. **常驻说明直接删行。** 老毛病回来时找不到原句。搬家用台账三列，不硬删。
3. **关票填了 `no change`，地图其实该改。** 字段闸拦不住撒谎。工头仍要打开地图对应行；结构变化却写无变化，等于下一窗拿旧图施工。
4. **进度页追加了、主线页没同步。** 指纹闸拒派，逼工头先改主线页。这是文档保鲜的硬挂钩：进度真源变了，窗口合同必须显式跟上。
