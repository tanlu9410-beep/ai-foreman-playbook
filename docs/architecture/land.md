# 合入门（land gate）

只接受隔离区封存的补丁。范围、冲突、能否应用、编译/导入、工具面、密钥形，任一步失败就停，补丁留在隔离区。隔离见 [`worktree.md`](worktree.md)；提交命令见 [`commit.md`](commit.md)。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。本页主体 **Does**。死清单与提交页同一条：**清单 ⊆ `allowed_paths`，否则拒**。不要把空清单或 `.` 当成合入侧「不限制」。

## 解决什么问题

小工自报「改了这些」不可靠。自动三路合并会把两张单的意图揉在一起。补丁看起来完整但新模块被 ignore 掉、工具 schema 漂移、密钥形字符串进仓——都不是工头用眼睛能稳定抓住的。主树有别人的未提交改动时，合入必须停，而不是盖过去。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 不参与机械闸；冲突停住之后如果涉及产品取舍再问 | 自己 `git apply`、自己清冲突 |
| 工头 AI | 看封存 diff 验收；过闸后派合入；冲突则重派或改范围 | 改检查结果换绿；用「先清主树」当合入条件 |
| 工人 AI | 在副本里做到封存 | 自己往主树 merge |
| 机器 | 按封存记录串行合入；失败写状态 | 猜测合并；回显匹配到的密钥正文 |

## 最小版怎么做

1. 只从封存记录合入（文件清单 + 补丁路径 + 补丁摘要 + `allowed_paths`）。
2. **清单 ⊆ `allowed_paths`；否则拒。** 空或 `.` 不是「不限制」。
3. 一把锁串行写主树。
4. 目标文件在主树已脏 → 停（conflict），不覆盖。
5. `git apply --check --index`，再 `git apply --index`。
6. 新增/修改的 Python：一律编译；约定包再 import（跳过会拉起整个进程的入口模块）。**import 会执行这些模块。**
7. 命中工具面路径 → 跑目录/一功能一工具测试。
8. 密钥形扫描：只返回路径，不回显匹配文本。
9. 任一步失败：写入明确状态，补丁留在隔离区。失败清理**只动本单清单路径**，不用整树 undo。

不要 `--3way`，不要 cherry-pick，不要临时移走主树脏改。

隔离副本不是沙箱：工人与主树同一系统用户；本页的 import 检查跑的是待合入代码。见 [`worktree.md`](worktree.md)。

## 我们现在的版本（2026-09）

入口按施工单 id 从库生成/复用记录，再走合入；成功则拆副本并可选 push。

### 记录是幂等屏障

- 已合入：直接返回记下的合入 sha，不再合一次。
- 可重试状态：已封存 / 锁忙 / 密钥挡住 / 冲突 / 导入检查失败 / 工具闸失败。其它状态拒。
- 补丁摘要对不上（被改过）→ 拒，不改状态。
- 不会用一份新封存覆盖已有合入/冲突记录。

### 范围外文件拒

- **Does。** 记录里的 added/modified/deleted 必须 ⊆ `allowed_paths`。绝对路径、`..` 拒。
- 工头看结果时，若副本文件已越界，先提示合入必拒。

### 冲突就停

- 一把锁串行写。
- 清单里任一文件主树工作区非空 → 冲突。
- 记录为新增但主树已有该路径 → 冲突。
- `apply --check` 或 apply 失败 → 冲突（index 锁则锁忙，可重试）。
- 不自动三路合并。

### `git apply --check --index` 再应用

- 普通补丁：整包 `--check --index`，再 `--index`。
- 静态资源可按路径逐个 include，减少半新半旧。其它冲突仍停。
- 暂存集必须正好等于清单（减去被判定为 no-op 的路径）。多暂存或少暂存都当冲突并清理。

### 编译 / 导入检查

- 新增+修改的 Python：一律编译；约定包再 import。脚本目录只编译（不是包，且有导入期副作用）。
- 跳过会拉起进程的入口模块（仍编译）。
- 失败写入失败列表，补丁留在隔离区。
- **边界：** import 即执行。合入门不是沙箱。

### 工具面

- 补丁碰到登记过的工具路径才跑：目录一致性测试 + 一功能一工具测试 + 目录渲染检查。超时或非零退出 → 工具闸失败。

### 密钥扫描

- 只扫暂存 diff 的**新增行**，以及新增 blob；不扫未改上下文（避免历史密钥挡住重提）。
- 命中只报路径（和行号），**不回显匹配文本**。
- 扫描器用通用形态，不读已配置的密钥值。

### 提交与失败清理

- 通过后：`git commit --only -m "<ticket> <task_id> …" -- <清单>`。`--only` 防止主树其它暂存混入。记下这次提交的 sha（见 [`commit.md`](commit.md)）。
- 失败：只 reset/checkout/unlink **清单路径**。不是整树 reset/clean。
- 合入成功后拆副本；push 由环境开关控制（失败不回滚已合入的提交）。

### 主树有脏改时文档不拷回

封存阶段会把报告类文档尝试拷回主树。主树该文件已有未提交改动，或内容已相对 `base_head` 漂移 → **不覆盖**，工人的版本只在副本/补丁目录。合入门合的是封存补丁里**排除**了这些报告路径的那一份。工头要报告，去副本，不要以为主树那份是工人写的。

## 必须由代码强制的规矩

1. 清单文件 ⊆ `allowed_paths`，否则拒。
2. 持锁；先 `git apply --check --index` 再 apply。
3. Python 编译；约定包 import（跳过进程入口模块）。
4. 命中工具面路径必须通过目录测试。
5. 密钥形扫描只报位置，不报正文。
6. 任一步失败写入状态，补丁留在隔离区。
7. 封存之后清单文件在主树变脏 → 停，不覆盖别人的未提交工作。

## 常见坑与我们怎么补的

1. **越界文件靠小工自报。** 补：合入从补丁重算清单，超出 `allowed_paths` 即拒；结果头提前警告。
2. **冲突自动 merge。** 两张单的意图混在一起。补：任何冲突停在隔离区，等工头判断。
3. **新文件被 ignore，合入后 import 崩。** 补：封存拒 ignored 新源文件；合入再编译/import。
4. **主树报告已脏，工人的报告被当成已上主树。** 补：脏则不拷回，明确提示；合入补丁不含这些报告路径。
5. **合入侧把空清单当不限制，与提交页打架。** 补：两边同一条——清单 ⊆ `allowed_paths`，否则拒。
