# 架构总览

本文描述公开仓的工头（foreman）—小工（worker）协作链。各环节都同时回答三件事：做什么、为什么做、怎么实现。系统的目标是把人的判断留在目标、授权和验收处，把可重复的纪律变成可验证的机器步骤。

这是一条私人施工流程的公开整理：文档为主，代码是能独立运行的节选，不是完整可部署系统。状态标签见 [`FOR-AI.md`](../../FOR-AI.md)： **Does** / **Does, awaiting live test** / **In progress** / **not implemented** / **Recommended**。施工单终态只有一份：`completed` | `failed` | `expired` | `blocked` | `cancelled` | `late_rejected`。

## 后台怎么分走冗余工作、怎么监督模型

owner 只说目标和授权。工头拆票、派单、验收。小工只施工。真正容易漏的，不是「谁会写代码」，而是一串必须记住的手续：卡住要不要重派、完工有没有人看、口头答应有没有兑现、范围有没有锁住、提交会不会误伤别人的脏树。以前这些靠工头和小工自己记；现在尽量写成机器步骤——漏了就拒单、催、或留下可复查的终态，而不是静默过去。

**卡住必须用固定格式。** 以前小工用自然语言说「做不下去了」，工头要猜要不要重派、同一跑次还要不要等。现在小工必须输出固定围栏和结构化字段（原因代码、摘要、需要工头给什么、证据）；任务进入终态 blocked，同一跑次结束，下一张新单才继续。

**每张施工单的终态必须被工头看见。** 以前靠工头记得去查结果。现在复核开关默认打开且不许关掉；完工后进入待审，工头要用 ack 收件。未收完的完工单、以及还在跑的单，会在工头下一拍提示里列出来，直到处理完。

**工头说了要做下一步却没动手。** 以前口头答应然后忘掉。现在系统识别「我去 / 我会 / 马上」这类承诺：若这一拍没有调用任何工具，下一拍工程提示会追问——现在做，或者说明为什么不做。同一句话只催有限次数。

**派单工具拒单并写原因。** 以前工头要自己记得票号、范围、授权和脏树。现在缺票号直接拒绝；施工单没写窄范围会警告将锁住整仓；隔离单在主树目标路径已有未提交改动就拒单；要求重启却没有 owner 当面原话就拒；试图关掉复核开关被拒。拒绝带明确原因，不进队列。

**提交与报告条款自动写进工单。** 以前靠口头或长文档让小工记住 git 禁令和报告落点。现在每张小工 brief 末尾都带上是否允许 commit/push 的条款，以及报告必须写到哪里；工单正文一旦提到提交，再追加死清单提交方式（只许按清单路径提交，禁止整树 add / stash / 回退）。

**失败要留下现场，报告要救得回来。** 以前失败后工头自己翻工作树猜做了什么。现在非成功终态自动记下范围内的改动摘要和报告文件是否存在，并提示先读报告再重派。只读或核对类工单若小工没把报告写到约定位置，引擎可代存一份（不覆盖已有文件）。

**记账不再走幸运路径。** 以前靠工头记得往票上补记录。现在施工单进入任一终态后，自动给关联票追加一条病历；同一任务不重复写。记账失败只留可见失败，不伪造成功，也不阻断主流程。漏记可以用补记工具重放。

**机器巡检补人眼。** 以前靠下次派单才发现服务不健康或资源告急。现在周期性只读检查服务健康、进程、磁盘内存、日志错误和事件积压，异常进入告警并带去重。巡检不替代工头验收，也不把施工队列的「有没有人 ack」交给同一套巡检。

下面各节是同一条链的分步说明。

## 开票（ticket creation）

**做什么：** owner 提出目标，foreman 把目标写成票，再在派单时把完成条件、任务类型（task kind）、后端池、允许改动的路径（`allowed_paths`）和验证方式写成施工合同。

**为什么：** 施工边界如果只存在于自然语言里，后续无法判断“小工做完了什么”以及“哪些文件可以进入主线”。票是产品事项，施工单是一次可验收的执行。

**怎么实现：** 票是票板上的一行（编号、内容、证据、状态）。目标、完成条件、`allowed_paths` 和任务类型是派单时的结构化字段，路径必须是仓库相对路径。缺票号的施工单直接拒绝。未写窄 `allowed_paths` 的写单**应拒单**（**In progress**：作者系统正在从「警告整仓」改成硬拒）。完成条件缺省时用占位语句（**Recommended** 改成硬拒），不把「有票」当成「合同完整」。小工流程结束不等于票已关闭。

## 派单（dispatch）

**做什么：** 派单入口读取路由总表（switchboard），按任务类型选择可用的小工池，跳过已暂停、授权不满足、额度已尽或接近上限的池；合适的任务进入队列，暂时不能启动的任务留在 queued。额度未知或过期快照不当作已满，也不当作有额度去抢先。工具目录（tool catalog）是另一张表，不承担路由。

**为什么：** 把“该派给谁”从临场猜测变成可审计的选择，也避免把任务塞给暂时不能接单的池。队列是等待集合，不应让调用者长时间阻塞。

**怎么实现：** 总表先做 schema 校验；通过则刷新一份 last-good 快照。坏表回退到 last-good 并带警告；两份都不可用时，依赖总表选型的派单拒绝。创建施工单时记下解析后的池、任务类型和权重，任务以 queued 落库。容量判断发生在认领：轮询器按入队顺序，在同一写事务里检查并发与路径锁再把符合条件的记录改为 running。工人撞上自己的时限由适配器标过期；常驻循环扫 queued/running 的收口是 **Recommended / not implemented**。认领后从未拉起进程的记录退回队列，已经拉起但进程消失的 running 记为失败。超时自动续跑会**另开一张单、再计一次费**。

## 隔离副本（isolated worktree）

**做什么：** 小工在独立副本中读取基线并施工，主副本的既有脏改动不搬走、不覆盖；副本结束后封存补丁、文件清单和校验信息。

**为什么：** 验收前不应让半成品进入主线，也不能用清理主副本的方式制造“干净环境”。隔离副本同时保护并行任务与 owner 已有的未提交工作。

**怎么实现：** 隔离副本从主仓当前 HEAD 拉出独立 git worktree，并拷贝本单点名的未跟踪依赖；开工时记录基线提交和依赖摘要。派隔离单时，若主树里本单 `allowed_paths` 已有未提交改动，创建即拒绝，避免开工后对着脏基线施工。副本是仓库快照，不把运行时数据目录或凭据文件挂进去；仓库里已经跟踪的文件仍随基线出现。封存物按新增、修改、删除列出（含二进制），并绑定补丁摘要。合入前再核对应摘要、以及主树目标文件是否已被别人改过。

隔离副本**不是沙箱**。工人与主树同一系统用户；合入门的 import 检查会执行待合入代码。它保护脏树和并行任务，不降权、不关进笼子。

## 合入门（land gate）

**做什么：** 合入程序只接受封存补丁，依次检查 `allowed_paths`、主副本目标文件是否有冲突、补丁能否安全应用、Python 文件能否编译和导入、工具规矩测试、密钥形扫描，任何冲突即停止。

**为什么：** 文件白名单防止范围漂移； import 自检防止“补丁看起来完整但新模块没进来”；工具规矩和密钥扫描分别守住接口契约与意外泄露。冲突时自动猜测合并会把两个任务的意图混在一起，因此必须停在隔离区等待判断。

**怎么实现：** 合入前从封存记录得到文件集合，与 `allowed_paths` 做路径级比对：**清单 ⊆ `allowed_paths`，否则拒**。用锁串行化写入，先 `git apply --check --index` 再应用。对新增和修改的 Python 文件一律编译；对约定包内的模块再做 import（明确跳过会拉起整个进程的入口模块；**import 会执行这些模块**）。命中工具路径时运行固定的工具目录测试。扫描只返回命中位置，不回显匹配文本。任一步失败都写入明确状态，补丁留在隔离区。

## 提交规约（commit contract）

**做什么：** 提交只允许使用票中列出的文件，使用 `git commit --only` 逐项指定路径；禁止整树 add、整树提交、stash、checkout、reset、restore 或清理工作树。

**为什么：** 长期脏树是正常协作状态，整树操作会把别人的改动带走或抹掉。显式文件清单让提交边界可复核，也使越界改动保持可见而不是被顺手吞掉。

**怎么实现：** 合入记录保存死清单（可提交的路径；**清单 ⊆ `allowed_paths`，否则拒**）。合入提交由门禁执行：核对目标文件现状后，用 `git commit --only` 只提交清单路径。清单外的改动不暂存、不提交。提交失败则清理本次暂存并回报原因，不用整树回退命令“试一下再恢复”。小工侧同一套禁令以条款形式写进工单正文，靠门禁而不是自觉来守合入。握手句旁边没有死清单 → **Recommended / not implemented** 在创建侧硬拒；合入侧已经按 ⊆ 执行。

## 重启队列（restart queue）

**做什么：** 需要重启的请求先入队；只有存在 owner 当面作出的原话授权，且服务空闲时才执行。完成后回执列出本次一并上线的提交。

**为什么：** 重启会改变正在运行的代码，必须把人的明确授权、正确时机和实际上线内容绑在一起；排队可以把陆续到来的重启理由并到同一次执行，减少打断。

**怎么实现：** 入队时必须带上 owner 原话，并在最近一段授权窗口的用户消息里做**子串**核对；缺原话、对不上或带否定，请求直接拒绝。子串核对的局限见 [`restart.md`](restart.md)。进行中的请求会暂停新的施工认领（闸读失败时认领暂停会 fail-open，**不告警**）。执行器等到连续空闲后再重启；新的理由在仍为 pending 时追加到同一条请求上，而不是另开互不相认的批次。执行完成写入成功或失败，回执按实际变更列出顺带上线的提交。对外说明只讲授权是否核过，不展示原话正文。这是**上新重启**。进程死了把原进程拉起来是**挂了拉活**，见 [`RESCUE.md`](../../RESCUE.md)。

## 自动记账（automatic casefile）

**做什么：** 每张施工单进入任一终态时，自动给关联票追加一条病历（casefile）；重复投递幂等，并发写入不丢历史；失败时抓取快照，保证报告仍可取回。

**为什么：** 记账不能只挂在“主动通知”这条幸运路径上，否则静默完成、取消、过期和异常退出都会失踪。病历把施工证据与票状态分开保存，方便追溯而不让失败阻断主流程。

**怎么实现：** 终态持久化之后再写病历，失败不影响主流程。以任务标识去重；同一票的创建与追加共用一把锁，新文件用独占创建，避免覆盖已有历史。任务失败另存现场快照（范围内改动摘要和报告是否存在），漏记可用补记工具重放。自动记账失败只留可见失败，不伪造成功。

## 巡检与告警（patrol and alerting）

**做什么：** 周期性检查服务健康、进程存活、磁盘与内存、日志错误和事件积压；异常进入告警，报告证据位置。施工队列是否在前进，则靠认领恢复、过期收口，以及工头提示里的未 ack / 在跑清单。

**为什么：** “没有报错”不等于系统在前进。死进程、卡住的待审和资源告急都需要在用户再次派单前显现。

**怎么实现：** 巡检器只读运行状态，使用明确阈值和告警去重；每项检查有结果和时间戳。告警发送失败不改变原始检测结果，下一轮仍可重试。报告只包含必要摘要。队列侧的过期、死进程和未审完工由派单与工头提示处理，不混进同一套主机巡检。

## 工头验收（foreman acceptance）

**做什么：** foreman 读取补丁 diff、测试结果、合入门报告和病历，亲自抽查关键路径，确认完成条件后才接受；绿色报告不等于验收。

**为什么：** 自动检查擅长发现机械违规，却不能判断改动是否真正解决目标、是否遗漏产品语义，或是否把范围扩大。验收权必须留在能理解目标的人这一侧。

**怎么实现：** 施工单 completed 只表示小工流程已结束，并进入待审；工头 ack 之后才算看过。票的关闭是另一次明确决定。发现问题就重派或开新票，不修改检查结果来换绿。机器不代替工头写下抽查结论。

## 工具面规矩（tool surface rules）

### 一个功能一个工具

一个功能只保留一个对外工具（one capability per tool）；同一功能的读取、检查、写入等行为用 `action` 区分，而不是复制出多个近似工具名。工具目录（tool catalog）记录能力、动作、输入和权限，测试验证目录与运行时注册一致。

### 按窗口冻结工具表

每个工作窗口开始时冻结一份工具表（catalog snapshot），窗口内不动态换 schema；工具升级后由新窗口加载新版本。这样同一轮判断看到的接口稳定，旧结果也能对应当时的目录版本。

## 从踩坑里长出来的规矩

1. **新文件被忽略 → 合入前做 import 自检。** 被忽略规则吞掉的新模块会让代码引用补丁里并不存在的文件；合入门必须从补丁文件集合检查新增模块，并执行编译与 import。
2. **主副本有脏改 → 派隔离单时就停，合入时再停一次。** 主树里本单路径已有未提交改动则拒绝创建隔离单，避免对着脏基线施工；合入前若目标文件又被改过，补丁留在隔离区，不覆盖别人的未提交工作。
3. **小工越过范围 → `allowed_paths` 做硬闸。** 只看小工自报的“改了这些”不可靠；合入记录从补丁重算文件清单，任何清单外文件都拒绝。
4. **整树操作污染协作 → 提交只用显式清单。** `add .`、整树提交和回退命令会误伤别人的脏改；合入提交只接受 `git commit --only` 与记录中的路径。
5. **单测绿色但接口漂移 → 工具门固定检查。** 工具 schema、目录和运行时注册必须一起测；命中工具面文件时自动运行目录一致性与“一功能一工具”测试。
6. **敏感字符串混入补丁 → 合入前扫描。** 隔离副本不挂运行时凭据；合入门仍对补丁做密钥形态扫描，只报告位置，不打印值。
7. **排队重启顺带别人的提交 → 回执列全实际上线内容。** 重启执行器以实际变更为准，回执逐项列出顺带上线的提交，使“顺便上线”可追查。
8. **绿色报告被误当验收 → foreman 必须亲查 diff。** 自动检查只证明规则和测试通过；完工待审必须由工头 ack，不能由小工的成功状态代替。
