# 前缀怎么改

状态：2026-09。读者是要照着搭体系的 AI。工具目录按窗冻结 **Does**。说明文件（手册 / 项目说明）按窗冻结 **not implemented**。状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。

## 解决什么问题

常驻说明和工具 schema 坐在模型前缀里。窗口中途改它们，等于悄悄换了模型以为自己所在的世界，并可能作废提示缓存、让人再付一次冷启动。把一次性事故的补丁写进每轮都读的前缀，前缀会无限膨胀，而且改一次就全窗失效。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 批准前缀批次（攒一批再换） | 为一条情境性提醒批准改手册 |
| 工头 AI | 把改动攒进批次；情境性修补放到出事地点 | 未获批次授权就改工具说明 / 手册 |
| 后台机器 | 冻结本窗已绑定的工具表 | 在窗口活着时改它看见的 schema |

## 最小版怎么做

1. **常驻说明只放每轮都要用的、根本性的话。** 身份、分工、硬禁令。事故补丁不进这里。
2. **工具说明改动按窗生效。** 改目录或 schema 只进入**之后新开的窗**。已开窗继续用开窗时那份。
3. **每轮注入的文字不要指望被冻结。** 待审清单、承诺追问、工具调用后的脚注，走回合信封或钩子，不写进冻结前缀。
4. **情境性修补放在出事地点。** 搜索结果后的提醒用工具后置钩子；某工具的弹出说明用工具自己的返回；不要写进手册。
5. **删行进改动台账。** 前缀里删掉的句子记「删了什么、为什么、哪次批次」，否则下一窗会把旧句再写回去。
6. 在说明文件按窗冻结实现之前：把手册编辑当作「窗与窗之间安装」，人没点这批就不要改。

**冻结的兼容契约：** 实现改了，旧窗看见的说明仍是绑定当时那一份。冻结名解析不到 → **fail-closed**，不要悄悄换一把新工具。显式换供应商或目录，活窗失败即关。

## 我们现在的版本（2026-09）

- **Does。工具表按窗冻结。** 窗口第一次用工具面时，把目录快照进库；后续回合读快照。活目录改了只影响新窗。装配时把快照交给工具通道，旧窗可继续看到当时的工具名。
- **Does。绑定后不因唤醒/杀死会话/权限翻转而换表。** 见 [`tools.md`](tools.md)。
- **Does。情境性修补：搜索后置提醒。** 内置搜索的后置钩子追加一段固定脚注，告诉模型结果末尾那句出处提示是搜索工具自带的，不是注入、不是系统警告。其它工具 no-op。钩子异常吞掉，以免丢掉工具结果。续跑不重复挂载。
- **Does。每轮注入、不被工具快照冻结的文字。** 工头下一拍提示里的未 ack / 在跑清单、以及「说了要做却没调用工具」的追问，走回合组装，不进工具夹具。
- **not implemented。说明文件按窗冻结。** 手册 / 项目说明仍是磁盘上的活文件；进程或窗口重读就会看到新字。在闸门落地前，前缀文件默认不动；工单必须写明「本批允许前缀改动」。按设计而不是按已强制行为来用。
- **Recommended。删行进改动台账。** 用手册与专项笔记记录「删了哪句、因为哪次事故」，没有单独的硬闸。公开实现做一份 no-delete 的台账即可：批次、删句、原因、生效窗口。
- **Recommended。常驻说明保持短。** 同一教训写进手册两次，第三次应变成代码闸（见 [`review.md`](review.md)）。

## 必须由代码强制的规矩

（仅限已经 Does 的子集。）

1. 已开窗的工具夹具不得被后来的活夹具覆盖。
2. 不得因为唤醒、杀死会话或权限变化而重新绑定工具表。
3. 命中工具面文件的合入，没有通过目录测试不得合入（见 [`tools.md`](tools.md)）。
4. 情境性脚注不得改写工具表；后置钩子只追加上下文。
5. 冻结名找不到 → fail-closed。

说明文件冻结、删行台账、批次授权本身：**Recommended** 用流程守，尚未变成硬闸。

## 常见坑与我们怎么补的

1. **把「模型刚才踩的坑」写进每轮都读的手册，手册变长，每次冷启动。** 补：手册只留根本句；补丁放钩子、工具返回或票的病历。
2. **改工具说明的当下，所有开窗一起换世界。** 补：工具表按窗快照。说明文件还没有同等闸，所以改手册要等人批批次、并尽量在窗间安装。
3. **把每轮才知道的清单（待审、在跑）写进冻结前缀，清单立刻过期。** 补：这些走回合注入，明确标成不被冻结。
4. **删了一句前缀却不记账，下一窗「补文档」时又写回去。** 补：删行进台账（Recommended）；同一教训第三次应变代码。
5. **实现已经改了，旧窗还按新说明调用，名字对不上就换一把。** 补：旧窗说明仍是旧的；找不到 fail-closed。
