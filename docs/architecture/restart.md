# 重启要人点头

状态：2026-09。读者是要照着搭体系的 AI。拼车 **Does, awaiting live test**（代码在，两席同时上车的现网路径尚未证明）。这是**上新重启**（把新代码送上线）。进程死了把原进程拉起来是**挂了拉活**，走 [`RESCUE.md`](../../RESCUE.md)，不要混成一次上新。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。

## 解决什么问题

重启会换掉正在跑的代码。旧窗口里随口说的「重启一下」不是授权；一张一张点会烧人的注意力，还会把别人刚合入的提交悄悄带上线。没有排队和空闲门，会在人还在说话时把窗打断。能在机器上动手，不等于已经授权。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 当面点头上线 | 自己跑重启命令、自己等空闲 |
| 工头 AI | 写理由、贴最近授权窗口里的原话、上车并就绪 | 自己在对话进程里重启；编造或改写原话 |
| 后台机器 | 剥标签、核原话、排队拼车、等空闲、执行一次、写回执 | 产品判断；把读不到的闸文件当成空车 |
| 救火队 | 主 AI / 聊天服务挂了时按急救页拉活或停 | 把拉活当成上新；趁乱合入未点头的提交 |

## 最小版怎么做

第一周只要服务真在跑，就先做这一组，拼车可以等第二席出现再加：

1. 入队必须带人的当面原话；到最近一段授权窗口（建议 **30 分钟**）的用户消息里做子串核对。缺、对不上、旁边有否定词 → 拒绝。
2. 工头只在回复末尾写重启标签；系统剥掉标签、入队、派执行器。工头进程不自己重启。标签名用 `<restart-request>…</restart-request>`（未闭合记 `unclosed`）。
3. 执行器等到「聊天回合空闲」再动：连续两次轮询，进行中的对话回合与不能活过重启的工人都是 0。
4. 只重启一次，检查健康接口与新进程，写回执。回执按**执行时**的 `HEAD` 差列出实际上线的提交，含顺带上车的。
5. 对外文本只说授权核过没有、新进程起来没有、顺带上线了哪些票号，**不回显原话正文**。

拼车可以后做：多张独立重启请求上一辆车，全员就绪才走；超员排下一辆。闸文件最小形状见 [`FOR-AI.md`](../../FOR-AI.md) §5。

### 授权原话子串核对的局限（如实）

核对是**字面子串**，不是理解：

- 授权窗口内用户消息里找这段原话；短于 2 字拒。
- 命中处两侧一小段里出现否定词（不要 / 别 / 先不 / 不可以 / 不行 / 等下 / 等一下）→ 拒。
- 碰巧相同的子串算数；换一种说法不算。
- 窗口按经过的时间算，不是「这一段对话」。
- 对不上这句话是在回谁。

拿不准就用白话再问一次。过期的句子不要凑数。

## 我们现在的版本（2026-09）

未在现网两席同车证明的标 **Does, awaiting live test**。

- **Does。重启标签由系统拿走，工头进程不执行重启。** 回复末尾的 `<restart-request>…</restart-request>` 从可见气泡剥掉；未闭合记 `unclosed`。处理器只入队普通施工单，从不自己跑执行器。
- **Does。原话对最近 30 分钟用户消息做逐字核对。** 缺字段、短于 2 字、窗口内找不到、或原话两侧约 12 字内有否定词 → 拒绝。同一条消息只处理一次。局限见上。
- **Does。派单闸：`task_kind=restart` 没有授权原话直接拒绝。**
- **Does。拼车状态机。** 一辆车：`boarding`（认领仍开）→ `departing`（有授权记录且全员 `ready`，认领仍开以便执行单能被领）→ `pending`（执行器发车，新施工认领暂停）→ `restarting` → `done`/`failed`（有下一辆则升上来）。一车一个执行单。新乘客在 `departing`/`pending` 上车会退回 `boarding`。`restarting` 时新乘客进下一辆。
- **Does, awaiting live test。两席同车上车。** 单元测试在；不要对人说现网两席同车已经跑通。
- **Does。闸文件读不到必须拒绝，不得降级成空车。** 文件不存在才是空。存在但打不开、不是 JSON、不是对象 → 读失败。执行器碰到读失败或缺乘客却带着执行单 id，拒绝并**不**调用会覆盖乘客名单的请求。写入目标权限要让执行器读得到。认领暂停那条路径对坏闸 **fail-open**，以免永久卡死队列，**不告警**；那不是「当成空车开新车」。
- **Does。等聊天回合空闲。** 轮询：对话未完成行 + 活不过重启的工人。连续两次都空才进入 `restarting`。默认最多等 30 分钟，超时失败、不重启。
- **Does。回执按实际变更列提交。** 相对上次成功重启的 `HEAD` 做日志；列不出就写「未知」，不猜。提交标题里多出来的票号记为顺带上线。
- **Recommended。** 回执落盘不要回显授权原话。对外通知已经不带原话。公开实现按「只报是否核过」做。

## 必须由代码强制的规矩

1. 没有人的当面原话 → 不能入队、不能派 `task_kind=restart`。
2. 原话必须出现在最近授权窗口的用户消息里；过期或带否定 → 拒绝，不要用更早的句子凑数。
3. 工头对话进程禁止直接重启；只写标签或派执行器。
4. 执行前必须看到连续空闲；超时只写失败回执，不重启。
5. 闸文件存在但读不到 → 拒绝。禁止当成「没有车」去覆盖乘客。
6. 回执的提交清单在执行时从真实 `HEAD` 差计算，不在入队时猜测。
7. `pending`/`restarting` 暂停新的施工认领；认领暂停超时可 fail-open（**不告警**），发车本身没有超时。

## 常见坑与我们怎么补的

1. **旧窗口的口头同意被当成授权。** 补：授权窗口（默认 30 分钟）+ 逐字核对 + 否定词；过期就再问一句白话。子串局限见上。
2. **闸文件跨用户读不到，执行器当成空车，把车上的人抹掉。** 补：读不到拒绝；共享文件权限；执行单 id 对不上就跳过、不改闸。
3. **排队重启把别人刚合入的提交也带上线，回执却只写自己那张票。** 补：回执列 `HEAD` 差里的每一笔，并标出顺带票号。
4. **重启卡在「像在等派单」。** 补：空闲门看的是聊天回合和活不过重启的工人，不是施工队列；新单在排队期间仍可入队。
5. **本地能动手就自己重启。** 补：操作能力不是授权。上新走闸；挂了拉活走急救页。
