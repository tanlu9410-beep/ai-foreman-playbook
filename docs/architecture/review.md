# 监督层

状态：2026-09。读者是要照着搭体系的 AI。这不是聊天里的第二个人格，是检查工头和工人有没有真的往前走的一层。机器催未审单属完整版，第一周不必做。状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。本页主体 **Does**。

施工单终态：`completed` | `failed` | `expired` | `blocked` | `cancelled` | `late_rejected`。非成功终态盖现场快照。

## 解决什么问题

工头口头说「我去做」，然后这一拍没调用任何工具。工人说「做完了」，其实没改、或改了别的。服务在两次探访之间死掉。失败后现场被下一轮盖掉，重派的人看不见盘上已有什么。绿色测试被当成验收。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 要不要关票、要不要花钱、要不要上线 | 自己翻补丁，除非想看 |
| 工头 AI | 打开 diff 与测试 diff 验收；ack；重派或开新票 | 凭工人「done」或全绿测试自动关票；改弱断言换绿 |
| 工人 AI | 做不下去就打 blocker 围栏并停 | 同一 `task_id` 上接着改；把失败说成成功 |
| 后台机器 | 待审清单、承诺追问、现场快照、代存报告、主机巡检 | 代替工头写下抽查结论；巡检施工队列的 ack |
| 救火队 | 主 AI 挂了时按急救页停、拉活、留记录 | 把拉活当成上新验收 |

## 最小版怎么做

第一周：工头亲自看 diff。机器催办可以后加。

1. 工人流程结束只表示进程结束，进入待审。工头 ack 才算看过。关票是另一次决定。
2. 验收读补丁 diff 和测试 diff，不读工人的自我总结当事实。
3. 做不下去：回复末尾打固定围栏 + JSON（原因码、摘要、需要工头给什么、证据）。任务进入终态 `blocked`；恢复用新 `task_id`。
4. 非成功终态盖一份现场快照：范围内 `git status`、约定报告文件在不在。不读文件正文。
5. **Recommended：** 只读/核对类工单若约定了报告路径而工人没写，引擎可代存一份，不覆盖已有文件。
6. **Recommended：** 换一家没读过私仓的模型，只读文档复述体系（冷读），当文档验收，不当运行验收。主 AI 挂了则不是冷读，是救火，见 [`RESCUE.md`](../../RESCUE.md)。

围栏形状（文末、只认最后一次）：

```text
<<<BLOCKER>>>
{"code":"need_decision","summary":"…","need_from_foreman":"…","evidence":"…"}
<<<END_BLOCKER>>>
```

允许的 code：`need_decision` / `need_brief` / `contradiction` / `missing_input` / `auth_required` / `malformed_blocker`。

## 我们现在的版本（2026-09）

- **Does。完工 ≠ 验收。** `review_required=false` 在创建时拒绝。工人 `completed` 进入待审；ack 才写下已审时间。关票走单独的关票申请，不是施工单终态。
- **Does。未验收催办。** 工头下一拍提示列出本席未 ack 与在跑的单（有条数上限）。查库失败或非工头窗不加字（fail-closed）。
- **Does。说了没做追问。** 识别「我去 / 我会 / 等下 / 接下来 / 马上 / 回头」这类承诺；若这一拍零工具调用，下一拍工程提示追问「现在做，或者说明为什么不做」。同一句哈希每窗最多催有限次。句首有条件标记（完 / 之后 / 如果…）的不催。
- **Does。blocker 只认文末围栏。** 只认最后一次出现且必须在正文尾巴；中间提及不算。坏 JSON 记 `malformed_blocker`。任务打成终态 `blocked`，恢复用新单。
- **Does。失败现场快照，不读正文。** 非成功终态盖范围内工作区状态、报告路径是否存在。绝对路径、`..`、超长路径丢弃。
- **Does。只读报告可代存。** 约定了安全的文档路径且文件还不存在时，引擎把工人最终文本写进去，带引擎标记，绝不覆盖。
- **Does。巡检绿 / 黄 / 红。** 只读：健康接口、进程、磁盘内存、日志错误、事件积压。红行发告警（带冷却与每轮上限）；绿/黄只进最新快照。巡检不看施工队列有没有人 ack。
- **Recommended。验收读 diff，不许改弱断言。** 没有机械闸能判断「这条 assert 是不是被改弱了」。工头必须打开测试 diff。发现为了换绿而改断言 → 拒收、重派。合入门只证明规则测试仍在跑，不证明产品语义。
- **Recommended。冷读测试。** 换一家没见过本仓的模型，只给 README + FOR-AI + 本目录，让它复述：体系全貌、第一周先搭什么、人/AI/机器各管什么。复述漂移就改文档，不改模型。这是文档验收，不是运行验收。

## 必须由代码强制的规矩

1. 不得把 `review_required` 关掉。
2. blocker 围栏必须在正文尾巴；非终态不得把同一 `task_id` 从 `blocked` 拉回 `running`。
3. salvage 只记路径级状态，不读、不回显文件内容。
4. 代存报告不得覆盖已有文件；路径必须落在约定的文档目录。
5. 巡检用明确的绿/黄/红，且不得声称自己在看施工队列。
6. 承诺追问有次数上限，避免死循环刷屏。

## 常见坑与我们怎么补的

1. **绿色报告被当成验收。** 补：完工进待审；工头必须 ack；关票另走申请。提示里一直列未 ack。
2. **工人在正文中间写了「卡住了」，工头猜要不要重派。** 补：只认文末结构化围栏；同一跑次结束。
3. **失败后重派，把盘上已有的半成品覆盖掉。** 补：salvage 提示先读报告；代存不覆盖。
4. **主机不健康，直到下次有人派单才发现。** 补：周期只读巡检，红行告警。它不替代 ack。
5. **病历写失败没人知道。** 补：fail-open 必须标成可见失败；**没有告警**。见 [`ticket.md`](ticket.md)。
