# 多个 AI 席位

状态：2026-09。读者是要照着搭体系的 AI。工头席称 **工头席 A / 工头席 B**。私人聊天窗称 **私人聊天窗**，本文不展开。第三席「只读参谋」**In progress**。状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。

施工单终态（一份，与票板/派单相同）：`completed` | `failed` | `expired` | `blocked` | `cancelled` | `late_rejected`。

## 解决什么问题

两扇工头窗对着同一块票板，会把同一张票派两次，或在人没点头的情况下互相传话。席位如果按「我是谁」而不是「现在干什么」来分，换模型、换窗口就会抢活或漏活。共用的重启、额度、主树路径也需要拼车，而不是各开一辆。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 批准跨席传话；决定要不要加席 | 自己在两窗之间复制粘贴工程上下文 |
| 工头 AI | 按活拆单、只认领自己这席还没被占的票、写给对方的短消息 | 替另一席关票；不经人批把内容投进对方窗 |
| 私人聊天窗 AI | 只派只读调研单（已有闸） | 派写入 / 验收 / 重启 |
| 后台机器 | 席位表、票互斥、待批队列、回执、拼车闸 | 产品判断；静默截断超长传话 |

## 最小版怎么做

两席之前先把单席跑通。痛点出现再加：

1. **席位表。** 每扇工头窗一行：窗口 id → 席位名。缺行有默认席，不要靠窗口标题猜。
2. **票互斥。** 创建施工单时，若另一扇工头窗已有同一票号的非终态单、或终态但未 ack，拒绝。同一窗不挡自己。
3. **跨席传话要人批。** 写入待批队列，人放行才投到目标窗；驳回不投。写回执给发送席。跨席传话默认由人放行。严格说这一步可以交给机器，但作者喜欢每条扫一眼，知道两张桌子在聊什么。
4. **内容有硬上限。** 超限报实际字数，禁止静默截断。
5. **共用资源拼车。** 重启见 [`restart.md`](restart.md)。额度与路径锁走派单总表，不在席位之间各记一套。

**Recommended：** 每席默认只看见自己的待审清单，避免两席抢着 ack 同一张。

## 我们现在的版本（2026-09）

- **Does。席位表。** 按窗口登记席位。按席位挑「最新一扇工头窗」，排除调用方自己。非法 / 缺行落到默认席，不报 500。固定导航窗永远不是工头。
- **Does。按活分工，不按身份。** 席位是窗口上的角色标记，不是某个人格。谁接哪类活由派单总表的 `task_kind` → 工人池决定（见 [`dispatch.md`](dispatch.md)）。两席都可以派单，互斥的是**票**，不是模型名。
- **Does。票互斥。** 工头创建时扫描施工单：另一扇工头窗持有相同票，且状态非终态、或终态但仍待审未 ack → 拒绝。非工头调用方不走这道闸。终态集合即文首那一份。
- **Does。私人聊天窗只能派只读调研。** 非工头上下文且模式不是只读 → 拒绝。写入 / 核对请跨席交给工头。
- **Does。传话要人批，且有回执。** 写入待批队列，状态 pending；人批准后才投递到目标窗。驳回不投递，已决行留审计。发送席通过工头收件箱拿到「已放行 / 已拒绝」回执（系统来源，避免被「自己发给自己」过滤器吃掉）。
- **Does。超限拒绝、不截断。** 正文与事由有硬上限，报实际字数。写入前做注入筛查，命中拒收。每回合每窗有条数上限。
- **Does。席间收件箱 best-effort。** 投递盒读写失败不得把票板成功写成工具失败。重启回执也走同一盒子。
- **Does。共用重启拼车。** 两席上同一辆车，全员就绪才发；见 [`restart.md`](restart.md)。待实测的是现网两席同车，不是单席路径。
- **In progress。第三席「只读参谋」。** 设计上是第三张工头席，只做只读参谋、不持有写入票。代码尚未单独成席。私人聊天窗的只读派单闸不是这一席，不要混用。

## 必须由代码强制的规矩

1. 创建施工单没有票号 → 拒绝（与派单合同相同）。
2. 另一扇工头席已持有该票（未终态或终态未 ack）→ 拒绝创建。
3. 非工头席不得派写入 / 核对 / 重启单。
4. 跨席正文有硬上限；超限失败并报字数，禁止截断后当成功。
5. 跨席内容必须进人的待批队列；机器不得直接投进对方窗。
6. 收件箱坏了不得回滚已经成功的票板写入。

## 空隙（如实）

**并发占票。** 互斥是创建时扫描，不是跨席一把排他锁。两席同一瞬间创建同一票号，可能都过扫描。起跑前崩溃（认领了但没拉起）由队列退回 `queued`，见 [`dispatch.md`](dispatch.md)；那补的是认领，不是这道扫描。

## 常见坑与我们怎么补的

1. **两窗各派一张「同一件事」的单，主树打起来。** 补：票号互斥直到 ack；隔离副本再在路径上锁一次。
2. **工头把长上下文直接塞进另一席，人根本没看见。** 补：待批队列 + 人放行 + 回执；注入筛查。跨席传话默认由人放行。严格说这一步可以交给机器，但作者喜欢每条扫一眼，知道两张桌子在聊什么。
3. **超长消息被截成半句，对方当完整合同执行。** 补：超限拒绝，返回实际字数。
4. **收件箱挂了，写票工具也报失败，工头重试写出重复行。** 补：收件箱吞掉自己的错误，票板成功仍是成功。
