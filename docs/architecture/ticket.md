# 票板与病历

票是产品事项；施工单是一次可验收的执行。状态只活在票板上。病历只记流水。关票是另一次明确决定，不是小工流程结束。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。本页主体 **Does**。施工单终态（一份，与派单/席位相同）：`completed` | `failed` | `expired` | `blocked` | `cancelled` | `late_rejected`。

## 解决什么问题

没有票板时，下一窗只能翻聊天猜：哪些活还开着、谁说过做完、上次试过什么。口头「做完了」会变成真源；两扇工头席会派同一张活；归档之后再开票会撞号；关票时没人能回答「地图哪一行变了」。

没有病历时，施工单静默完成、取消、过期或异常退出都会失踪。下一次派单要靠工头记得去翻工作树。

## 交给谁

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| **人** | 优先级、要不要放弃一张票 | 记票号、写病历、分配下一号 |
| **工头 AI** | 开票、改状态、追加进展、关票（带证据和地图说明） | 用聊天当状态；在没证据时关票 |
| **工人 AI** | 按施工合同干活；需要时只往票面追加进展（不改状态） | 自己把票标成已完成 / 已放弃 |
| **机器** | 分配票号、拒无证据写入、单元格清洗、终态自动记账 | 产品判断；代替工头关票 |

## 最小版怎么做

### 票板

一份 **no-delete** 的 markdown 表（不删行，可原地改状态）。状态只活在最后一列。不要提供 delete。

列：`id` · `source` · `date` · `category` · `content` · `status`。

状态用你真的会区分的词，例如：待办 / 进行中 / 待审核 / 待验收 / 搁置 / 已完成 / 已放弃。

流程：

1. **开新票**：写入一行；票号由机器分配，不让模型自报；必须带证据锚点（文件路径、测试名、报告路径或 artifact id）。记忆不算。
2. **追加进展**：在同一行 `content` 末尾追加一段，不改状态、不改其它行。
3. **改状态**：独立动作；仍要证据。
4. **关票**：独立于「改状态」的动作；只接受终态（已完成 / 已放弃）；必须再写地图变更——进度页或系统地图哪一行变了，或字面 `no change`。
5. **看一张票**：读票板那一行（状态）+ 病历全文。没有病历不是错误。

单元格必须是单行：真换行会拆行，半角 `|` 会拆列。写入前把换行和 `|` 换成不会拆表的字符，超长拒绝、不截断。

### 病历

每张票一个 markdown 文件。头只写票号、一句话目标和「状态见票板」。下面按施工单终态追加，不覆盖：

```text
## <timestamp> · autolog
- work order: <id> (<pool>)
- terminal: completed | failed | blocked | cancelled | expired | late_rejected
- conclusion: <short>
- receipt: <path, test name, or none>
```

同一施工单 id 不写第二遍。不把聊天正文抄进病历。

### 归档

已完成行从主板搬到同目录的归档文件（建议文件名带日期）。主板变短，号段仍被占用。分配下一号时必须连归档一起扫。归档是整理，不是删除。

## 我们现在的版本（2026-09）

下列只抽象职责和格式，不是你必须沿用的文件名。

- **Does。no-delete、无 delete。** 票板工具只认追加 / 改状态 / 关票；delete 类词拒绝。
- **Does。状态真源在票板。** 读票返回票板行的状态 + 病历；病历头写明状态见票板。
- **Does。开票必带证据。** 所有写入缺证据拒绝。新票把证据写进内容列。
- **Does。票号机器分配。** 无票号的追加开新票；只扫表格首单元格号（不扫正文 `#123`），取低于异常号段上限的 max+1，再跳过已被主板和归档占用的号。
- **Does。进展追加不改状态。** 带票号的追加只在内容列末尾追加。更窄的追加工具只改内容列、禁止换行和 `|`、写后核对其它行与最后一列未动。
- **Does。关票独立、要地图说明。** 关票与改状态分开；必须写地图变更（进度页 / 系统地图哪一行，或 `no change`）。
- **Does。非工头席不能改状态或关票。** 只能追加开新票。
- **Does。病历自动记账。** 施工单进入终态后追加一条；以工单 id 去重；创建与追加同一把锁；新文件独占创建。失败 **fail-open**：不回滚已提交的终态行，**不告警**。漏记可用补记工具重放。
- **Does。归档参与号段。** 主板同目录的归档文件全部扫入占用集。把已完成行搬进这些文件是工头整理，不是自动删行。

## 必须由代码强制的规矩

1. 无票号的施工单创建直接拒绝。小工 `completed` 不是关票。
2. 写入票板必须有证据锚点；关票必须另给 `map_change`。缺哪个报哪个，不截断超长字段。
3. 不提供 delete。单元格清洗后仍必须是单行表，写后自检失败回滚。
4. 终态施工单给关联票追加病历；同一工单 id 不双写；记账失败只留可见失败，不伪造成功，也不阻断主流程。
5. 分配票号必须把归档文件里的号当作已占用。

**Recommended（现在不是硬拒）：** `map_change` 只检查字段在不在，不核对进度页/地图文件是否真的改了。关票时关联施工单仍待审只警告、不拦。你可以把这两条升级成硬拒。

## 空隙（如实）

- 病历写失败 fail-open，主流程当成功走完，**没有告警**。工头必须看见那一行，或把可见失败写上票板。
- 两席同时开同一张票的施工单：互斥是创建时扫描，不是跨席一把排他锁。见 [`seats.md`](seats.md)。

## 常见坑与我们怎么补的

1. **正文里的 `#123` 被当成票号。** 引用外部 issue 会把下一号抬走。只扫表格首单元格。
2. **归档后撞号。** 高号进了归档、主板看起来「最大号很小」，下一张会复用旧号。分配时主板+归档一起扫。
3. **只在「主动通知工头」时记账。** 取消、过期、进程消失会没有病历。终态持久化之后独立记账，不依赖通知路径。
4. **半角 `|` 或真换行写进单元格。** 表裂开，邻行错位。拒绝或替换这些字符；窄追加直接拒；宽写入换成不会拆表的字符后再写后自检。
