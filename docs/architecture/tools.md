# 工具面

状态：2026-09。读者是要照着搭体系的 AI。工具目录按窗冻结 **Does**；说明文件按窗冻结见 [`prefix.md`](prefix.md)（**not implemented**）。状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。

## 解决什么问题

工具一多，同一件事会裂成五个相近的名字；模型不知道用哪把，前缀也被撑冷。中途改 schema，当前窗口里上一轮的判断对不上这一轮的接口。罕用能力若全部常驻，每轮都付缓存成本。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 批准会改前缀的工具面批次 | 为一次偶发需求要求常驻新工具 |
| 工头 AI | 按目录调用；新能力先问「能否并进已有工具」 | 为图方便再注册一个近似名字 |
| 工人 AI | 只用工单允许的能力 | 改工具目录或 schema |
| 后台机器 | 冻结本窗工具表、执行预算、合入时跑目录测试 | 在窗口中途换 schema |

## 最小版怎么做

1. **一种能力一个工具。** 读 / 查 / 写用同一个名字加 `action`，不要并列出现两个近似名字在模型面前。
2. **常驻少数，罕用经转发。** 开窗只挂一小张固定表；其余经一个路由器（`action=list|call`，`name` 为准确工具名）。
3. **工具说明就是规矩落点。** 模型看见的那句目录从一张登记表生成，不要手写进冻结夹具后两份分叉。
4. **按窗快照。** 窗口第一次用工具面时把目录冻住；本窗后续回合沿用这份，即使上游夹具已改。新窗口吃新目录。
5. **每轮预算。** 工具调用有上限；用尽拒绝，不默默加额度。

合入命中工具面文件时，跑「目录一致 + 一功能一工具」测试，失败不得合入。

**冻结的兼容契约：** 实现改了，旧窗说明还是绑定当时那一份。冻结名解析不到 → **fail-closed**（不要悄悄换新工具）。显式换供应商或目录，活窗失败即关。

## 我们现在的版本（2026-09）

- **Does。固定台面：内置搜索 + 少数自定义。** 顺序钉死。活名单与夹具哈希不一致会断言失败。罕用经一个转发器：`action=list` 发现，`action=call` 按准确名字转发。常驻名不再出现在转发清单里。
- **Does。一种能力一个工具。** 同一前缀多名必须写入豁免表并写非空理由，否则测试红。合入若改工具策略 / 总线 / 目录 / 处理函数 / 夹具，必须跑目录测试与一功能一工具测试，外加目录渲染检查。
- **Does。工具说明从登记表生成。** 加工具是改这张表再跑渲染脚本，不要手改夹具里的目录句子。
- **Does。按窗快照工具表。** 有窗口 id 时，第一次把夹具写入快照表；之后读库存份。空窗口 id 回落到活夹具且不写快照。并发先提交的赢。装配时把这份快照交给工具通道，旧窗可继续使用已改名的旧工具名（别名仍可执行）。
- **Does。窗口绑定失败即关。** 首次认领绑定供应商 + 工具目录 id。杀死/唤醒/权限翻转不得换绑。显式换供应商或目录 → 失败即关。
- **Does。每轮预算。** 默认有上限。预算钩把剩余次数放到可变盒子里，续跑可把剩余打到 0 而不拆掉唤醒权限钩。剩余 ≤0 拒绝。唤醒轮预算是另一条开关。

## 必须由代码强制的规矩

1. 同前缀多名且不在豁免表（或理由为空）→ 测试失败，合入拒绝。
2. 命中工具面路径的合入必须跑目录一致性与一功能一工具检查。
3. 已绑定窗口不得因开关翻转而换工具表；换供应商/目录失败即关。
4. 本窗快照在第一次使用后不得被活夹具覆盖。
5. 预算用尽拒绝本次工具调用，不抬上限。
6. 路由器 `list` 不得把已合并家族的旧叶子名广告给模型（旧名可执行以伺候旧快照）。
7. 冻结名找不到 → fail-closed。

## 常见坑与我们怎么补的

1. **同一能力裂成五个工具名，模型每次都猜错。** 补：一功能一工具 + 豁免必须写理由 + 合入测试。
2. **改夹具的当下，所有开着的窗一起换前缀，旧判断作废并冷启动。** 补：按窗快照；新窗才吃新目录。旧名留别名。
3. **把罕用能力全部常驻，每轮前缀膨胀。** 补：常驻少数，其余经一个转发器，用 `action=list` 发现。
4. **目录句子手写进夹具，登记表改了夹具没改。** 补：夹具由渲染脚本从登记表生成，合入跑检查。
5. **实现改了，旧窗按新世界调用，找不到就换一把。** 补：旧窗说明仍是旧的；找不到 fail-closed。
