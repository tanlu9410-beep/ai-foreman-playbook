# 隔离副本（isolated worktree）

小工不在主树上改。从当前 `HEAD` 拉出独立 git worktree，封存后再走合入门。合入见 [`land.md`](land.md)；提交见 [`commit.md`](commit.md)；派单见 [`dispatch.md`](dispatch.md)。

状态标签见 [`FOR-AI.md`](../../FOR-AI.md)。本页主体 **Does**。

## 解决什么问题

在主树施工会盖掉人还没提交的改动，也会把两张单混在一起。「先把工作树清干净再开工」是丢别人补丁的标准办法。未提交文件本来就不在 `HEAD` 里，副本里看不见——若小工对着缺文件的基线做，合入时才发现对不上。

## 交给谁（人 / AI / 机器）

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 人 | 不需要为了让小工舒服去清主树 | 自己建 worktree、自己合入 |
| 工头 AI | 写窄 `allowed_paths`；主树目标路径已脏则先提交或改范围；验收封存补丁 | 把「先 stash / reset / clean」写进工单 |
| 工人 AI | 只在副本里改 | 把运行时数据、密钥目录挂进副本；假定能看见主树未提交文件；把副本当成沙箱 |
| 机器 | 建副本、记基线、封存、过期清扫 | 自动清主树；把凭据 bind 进副本 |

## 最小版怎么做

1. 开关打开时，写单（`edit_no_commit` / `verify`）从**当前 `HEAD`** `git worktree add --detach`。
2. 记录 `base_head`，以及本单点名的、已审的**未跟踪**依赖及其摘要。跟踪文件随基线出现；未提交改动和未点名的未跟踪文件**不会**出现在副本里。
3. 不把运行时数据目录、凭据文件挂进副本。仓库里已经跟踪的文件仍随 `HEAD` 出现。
4. 主树里本单 `allowed_paths` 已有未提交改动 → **创建即拒绝**（脏基线拒）。先提交再派，或把脏路径移出本单范围。
5. 收工封存：新增 / 修改 / 删除（含二进制）+ 补丁摘要。只从这份封存合入。
6. 清扫是显式维护，不挂在 create/seal 自动路径上。

提交类、重启类、运维类工单必须动真树（真分支、真 checkout），不要隔离。

**隔离副本不是沙箱。** 工人与主树同一系统用户。合入门的 import 检查会执行待合入代码。隔离只分开脏树和并行任务，不降权、不拦恶意或失手的进程去碰主机。把这条写进工单。

## 我们现在的版本（2026-09）

隔离由环境开关打开；副本目录由配置指定，不要写进工单正文。

### 从 HEAD 切

- **Does。** `git worktree add --detach` 到当前 `HEAD`，记下 `base_head`。
- 只在开关开、模式是写/核对、且 `task_kind` 不是 `commit` / `restart` / `ops` 时隔离。
- 主树虚拟环境若存在，副本里做目录符号链接，不复制。剥掉会让 git 打到主树的环境变量。

### 未提交文件副本看不到——先提交再派

- 副本是 `HEAD` 快照。主树已改未提交的内容不在副本里。
- 未跟踪依赖：仅当工单点名、且 git 确认为未跟踪文件时拷入，并记摘要。已跟踪的路径不能当「依赖」再拷一份。自动依赖只从工单文本里抽出的仓内候选、且确实未跟踪的文件。
- 因此：小工需要的基线文件必须先在主树提交（或作为已审未跟踪依赖点名）。否则他对着缺页施工。

### 脏基线拒

- **Does。创建前**（尚未写任务行）：看本单 `allowed_paths` 在主树是否已脏（忽略报告类路径）。脏则拒，避免白跑一发。
- **Does。拉起时再拒一次**：发现脏路径即失败，提示先提交。
- 报告类文档路径不参与脏基线判定，避免报告骨架挡住施工。

### 封存

- **Does。** 在副本里暂存范围内改动，按相对 `base_head` 列出 added/modified/deleted（含二进制、重命名拆成删+增），写出补丁与摘要。
- **Does。被忽略的新源文件拒封。** 范围内被 ignore 掉的源文件会导致「补丁看起来完整、合入后模块不存在」。不封。
- 空补丁直接拆掉副本。
- 报告类文档在封存时尝试拷回主树；主树该文件已脏则**不覆盖**，工人的版本只在副本/补丁目录。合入门本身不负责拷文档，见 [`land.md`](land.md)。

### 副本清理

- 合入成功后拆副本。
- 过期清扫只删配置目录下、超过年龄的 linked worktree。**不**从 create/seal 自动跑；显式维护时才调。

## 必须由代码强制的规矩

1. 主树本单 `allowed_paths` 已有未提交改动 → 拒绝创建隔离单。
2. 副本从当前 `HEAD` 切；不要把运行时数据或凭据目录 bind 进去。
3. 封存必须包含新增/修改/删除（含二进制）和补丁摘要；合入只认这份封存。
4. 范围内被 gitignore 掉的新源文件 → 拒绝封存，不要假装补丁完整。
5. 人不必、也不可用清主树来给小工制造「干净环境」。

## 常见坑与我们怎么补的

1. **未提交文件副本没有。** 小工「本地有啊」——那是主树。补：脏基线创建即拒；文档写明先提交再派，或把未跟踪依赖点名进工单。
2. **gitignore 吞掉新模块。** 封存看起来成功，合入后 import 失败。补：封存前扫范围内被忽略的源文件。合入侧再做编译/import，见 [`land.md`](land.md)。
3. **提交/重启/运维单被隔离。** 真分支、真进程、真 checkout 对不上副本。补：这些类型强制走主树。
4. **用 stash/reset 给小工腾地方。** 会把别人的脏改带走。补：隔离副本；工单禁整树命令，见 [`commit.md`](commit.md)。
5. **把隔离当成沙箱。** 同一用户、import 会跑代码。补：工单写明边界；救火时不要拿隔离副本做「试合入」。
