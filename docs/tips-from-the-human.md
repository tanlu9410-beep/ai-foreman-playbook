# 搭档的人总结的经验

## 写给你：跟 AI 合作的几条经验

这些是作者踩过的坑。不是规则，是提醒。

**1. AI 说「我知道了，下次不会了」，别信，先分辨。**
它换个窗口就忘了。你要判断的是：这是会反复遇到的问题，还是偶然一次？会反复的，让它做进系统里——变成代码、闸门、出事时弹出来的提醒。拿不准的，先记着，再遇到一次就做进去。

**2. 它开始「手搓宇宙」时，叫停。**
当你觉得它在用很复杂的办法解决一个问题，或者同一个 bug 已经修了三次，问它：你上网搜过吗？看过 GitHub 上别人怎么做的吗？真的要这么复杂吗？然后把你的需求重新说一遍，让它停下来想一想。不要让它为了解决你一个小问题造一个宇宙。

**3. 先定方案，再动手；审方案要审意图，不审能不能跑。**
做任何一套东西，都可以走这个顺序：讨论方案 → 上网抄抄别人的作业 → 写成方案 → 让另一个聪明的模型交叉审。审的时候别只问「能不能跑通」——直升机也能在地上开。要问：这是我要的东西吗？

**4. 数字漂亮，不等于做对了。**
模型天生偏爱能数出来的东西：通过率、测试绿了几条、超标降了多少。可很多事没法用数字衡量。作者就遇到过：一个改动让「超标轮数」从 67 降到 0，看起来完美；可抽几条真实内容一看，它砸掉的大多是有用的东西。验收还是要人来做，或者先跟模型把意图对得非常清楚。

**5. 它说「只能这样」时，问一句「为什么」。**
模型思路容易轴。它说「只能这样」的地方，往往藏着一个没说出口的前提。追问一句，前提摔出来了，路常常就不止一条。

**6. 把话说简单，毛病就出来了。**
讨论方案时，一定让模型用最简单的话讲清楚它打算怎么落地。这最容易暴露本质问题。代码好验证，交给模型就行；思路对不对，模型自己很难看出来，要你来看。

**7. 说明书会悄悄过期。**
系统在变，文档不一定跟着变。作者的系统说明书里就曾把一个早就不用的服务当成主角，没人发现，差点写进急救手册。隔一阵子让 AI 拿现实去核对一遍说明书，别只信文档。

**8. 它说「我记得是这样」，让它查。**
AI 越说得笃定，越值得让它拿证据。凭印象说的话，查一下常常就不对了。

**9. 卡住了就换个窗、换个模型。**
同一个问题反复搞不好，而且大概率是模型犯糊涂的时候，换一个窗口或者换一个模型。可能是它降智了，也可能是被前面的思路绊住了——引进一个新思路，往往就通了。
